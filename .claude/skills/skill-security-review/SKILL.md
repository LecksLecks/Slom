Прогони это ПЕРЕД `claude plugin install`, `npx skills add`, `claude plugin
marketplace add` или любым другим способом затащить сторонний код в среду
выполнения. Методика — то, что уже отработано вручную на Higgsfield,
ui-ux-pro-max, llm-council, superpowers, context7, instagram-skills; здесь
просто зафиксирована, чтобы не передумывать заново каждый раз.

## Шаг 1: Найди реальный источник

`WebSearch` даёт название/автора — не доверяй ему как источнику истины.
Подтверди: это тот репозиторий (не тайпсквоттинг похожего имени), реальный
владелец/организация, `git clone --depth 1` или прямой `curl` к
`raw.githubusercontent.com` — не полагайся на страницу репозитория как на
единственное подтверждение.

## Шаг 2: Доставай код напрямую, не пересказ

`WebFetch` **парафразирует** контент через маленькую модель — для секьюрити-
ревью это негодный источник, он может сгладить или пропустить существенную
деталь. Всегда: `git clone` во временную директорию (`scratchpad`, не в
рабочее дерево репозитория) или `curl` напрямую к raw-контенту. Читай
исходный текст файлов, не сводку.

## Шаг 3: Перечисли ВСЕ бандлы, не только заявленный

Установка одного скилла часто тащит больше, чем описано:
`.claude-plugin/marketplace.json` / `plugin.json` — сколько скиллов/агентов/
хуков/MCP-серверов реально внутри. `ui-ux-pro-max-skill` заявлялся как 1
скилл, оказалось 7 — если находишь несовпадение, это идёт в раскрытие
пользователю (шаг 7), не молча устанавливается как есть.

## Шаг 4: Скан на опасные паттерны

```
eval\(|exec\(|subprocess\.(call|Popen|run)|os\.system|os\.popen|
shell=True|urllib\.request\.urlopen|requests\.(get|post)|
base64\.b64decode|pickle\.loads|shutil\.rmtree|rm -rf|
curl .*\| *sh|wget .*\| *sh|__import__|nc -e|/dev/tcp/
```

Прогони по каждому исполняемому файлу (`.py`, `.js`, `.ts`, `.sh`, `.cmd`) во
ВСЕХ бандлах из шага 3, не только в файле, который назвали пользователю.

## Шаг 5: Каждый хит — в контекст, не по факту совпадения

Совпадение с паттерном — не приговор. Проверяй: путь захардкожен или из
пользовательского ввода? Команда идёт списком аргументов (`subprocess.run`
без `shell=True`) или через шелл-интерпретатор? Есть explicit opt-in
(переменная окружения, которую пользователь сам должен установить) или
срабатывает по умолчанию? Пример безопасного хита: `shutil.rmtree` на
жёстко заданном пути внутри dev-скрипта сборки — не проблема.
Пример небезопасного: `eval()` на данных, пришедших из сети.

## Шаг 6: Хуки — отдельный разбор

Хуки (`SessionStart` и т.п.) исполняются автоматически, без явного запроса
пользователя на каждый запуск — самый высокий риск в списке. Прочитай
исполняемый файл хука целиком: сеть? credentials? что именно попадает в
контекст сессии? Хук, который просто читает локальный файл и выводит его как
JSON-контекст — безопасен. Хук, который стучится наружу до какого-либо
действия пользователя — красный флаг.

## Шаг 7: Публикация/запись — дефолт безопасен?

Если инструмент может публиковать/удалять/тратить деньги — проверь дефолт.
Требует явного API-ключа, которого нет из коробки (как Publora/Context7)?
Не публикует без него — приемлемо. Публикует/действует без явного
opt-in — красный флаг, даже если это не «вредоносно» в классическом смысле.

## Шаг 8: Сверь заявленное с реальным, раскрой пользователю

Одним блоком перед установкой (или сразу после, если ставишь без
дополнительного подтверждения): что реально внутри, какие сетевые вызовы
куда, какие данные туда уходят, какой дефолт у публикации/записи, любое
расхождение с тем, что было заявлено при поиске/запросе. Раскрытие — не
опционально, даже если вердикт «безопасно».

## Красные флаги — не устанавливать / остановиться и спросить пользователя

- `eval`/`exec` на данных из сети без явного контроля пользователя.
- Обфусцированный код (base64-блобы вместо читаемого текста) без причины.
- Хук, отправляющий данные наружу до любого действия пользователя.
- Заявленный скоуп кардинально расходится с реальным бандлом, и это не
  раскрыто в описании самого репозитория.
- Учётные данные/ключи запрашиваются для базовой установки без понятной
  причины.

## Экономия токенов

Пиши компактно: результат — раскрытие находок (шаг 8), не пересказ каждого
шага методики. Таблицы вместо прозы там, где уместно. Экономь прозу вокруг
итогового раскрытия, не сам факт раскрытия — оно обязательно.
